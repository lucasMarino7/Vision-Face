Sobre o modelo

Este Modelo flask tem alta capacidade de escalonar o projeto, a estrtura dos diretórios no backend foram basendo nas apis de documentação oficial do flask e do flask-restx, porém qualquer atualização em que se achar necessário, deve-se alterar no backend, para que mantenha este modelo sempre atualizado ao mercado e esteja o mais profissional possível. Para fins didáticos e de melhor entendimento da estrutura e das funções utilizadas no backend, foi utilizado um simples exemplo de blog sobre resenhas de filmes e livros.
Nela os usuários podem fazer suas postagens de resenhas sobre filmes que assistiram ou de livros em que leram, tendo a possibilidade de permitir a visualização pública de suas postagens, ou se preferir, permitir apenas para a sua própria visualização.
E para um melhor gerenciamento dos usuários e da aplicação, podem ser criados usuário administradores, contendo privilégios sobre os demais usuários e recursos a mais da aplicação.
O modelo também inclui um API REST, totalmente documentada pelo swagger e protegida por authenticação, onde apenas usuários com niveis/roles administradores tem acesso sobre esse recurso.

Sobre os niveis/roles dos usuários

No blog há três niveis/roles de usuários:

Client

Os Clients são os usuário clientes da aplicação, onde não possuem nenhum nivel admintrativo e autorização de acesso as APIS, porém podem gerenciar suas próprias postagens e seus dados de cadastro na aplicação.

Sobre acesso e controle à API: Nenhum privilégio

Sobre os usuários clientes: Nenhum privilégio

Sobre os usuários administradores: Nenhum privilégio

Sobre o usuário super administrador: Nenhum privilégio

Admin

Sobre acesso e controle à API:

  • Possuem acesso à documentação swagger
  • Tem acesso a todos métodos REST sobre as APIS de livros, filmes e usuários

Sobre as APIS REST

Para um melhor nível de organização, as APIS REST está totalmente isoladas dos routes da web.
São documentadas pelo swagger, protegidas por authenticação JWT e possuem modelos de entrada de dados que auxiliam o usuário a ter o melhor aproveito das apis.
Todos seus routes incluem o sistema CRUD.
E para um melhor manuseio delas, elas foram divididas em:

  • Uma API para livros

    *Isso ainda vai mudar, para API para resenhas

  • Uma API para filmes

    *Isso ainda vai mudar, para API para resenhas

  • Uma API para os usuarios

    Onde contém todos os usuários cadastrados na aplicação, e dentro dela contém um subAPI para os niveis/roles dos usuários.

Sobre a Estrutura do backend

A Estrutura do backend foi baseada em exemplos oficiais das APIS do flask e flask-resxt, ela foi dividido da seguinte forma:

  • src
    (Diretório principal do projeto)
    • apis
      (Diretório separado da web, onde contém todas as funcionalidas e routes das apis)
      • __init__.py (inicialização da api, onde irá criar um blueprint separado somente para a api, importar e adicionar as namespaces filhos a ela)
      • namespace 1.py (namespace 1 filho da api)
      • namespace 2.py (namespace 2 filho da api)
      • ...
      • namespace N.py (namespace N filho da api)
    • models
      (Diretório models, onde conterá todas as tabelas sqlalchemy)
      • model 1.py
      • model 2.py
      • ...
      • model 3.py
    • schemas
      (Diretório schemas, onde conterá os schemas marshmallow)
      • schema 1.py
      • schema 2.py
      • ...
      • schema 3.py
    • server
      (Diretório server, responsável por criar, configurar e instanciar toda a aplicação)
      • app_factory.py (inicializa/cria o objeto flask (fábrica do flask))
      • config.py (configura a aplicação conforme seu modo (Produção, Depuração e teste))
      • extensions.py (instancia todas as extenções da aplicação)
      • instance.py (instancia e rodar a aplicação)
    • web
      (Diretório web ou core, separado da api, onde conterá todas as funcionalidas e routes da web)
      • forms
        (conterá os forms/formulários que serão utilizados nos routes)
        • form 1.py
        • form 2.py
        • ...
        • form 3.py
      • static
        (conterá arquivos css, js e imagens que serão utilizados nos routes)
        • images
          • img-1.png
          • img-2.png
          • ...
          • img-N.png
        • scripts
          (Os arquivos js de uso específicos de cada blueprint fazerão parte de seus respectivos diretórios cujo nome é o mesmo da blueprint, e aqueles arquivos que são de uso geral são deixadas na raiz do diretório)
          • blueprint 1
            (arquivos js de uso específico da blueprint 1)
            • blueprint-1-script-1.js
            • blueprint-1-script-2.js
            • ...
            • blueprint-1-script-N.js
          • blueprint 2
            (arquivos js de uso específico da blueprint 2)
            • blueprint-2-script-1.js
            • blueprint-2-script-2.js
            • ...
            • blueprint-2-script-N.js
          • ...
          • blueprint N
            (arquivos js de uso específico da blueprint N)
            • blueprint-N-script-1.js
            • blueprint-N-script-2.js
            • ...
            • blueprint-N-script-N.js
          • base.js (arquivo js de uso geral para todas as blueprints)
        • styles
          (Mesmo intuito de organização da pasta scripts)
          • blueprint 1
            • blueprint-1-style-1.css
            • blueprint-1-style-2.css
            • ...
            • blueprint-1-style-N.css
          • blueprint 2
            • blueprint-2-style-1.css
            • blueprint-2-style-2.css
            • ...
            • blueprint-2-style-N.css
          • ...
          • blueprint N
            • blueprint-N-style-1.css
            • blueprint-N-style-2.css
            • ...
            • blueprint-N-style-N.css
          • base.css
      • templates
        (Mesmo intuito de organização da pasta scripts)
        • blueprint 1
          • blueprint-1-template-1.html
          • blueprint-1-template-2.html
          • ...
          • blueprint-1-template-N.html
        • blueprint 2
          • blueprint-2-template-1.html
          • blueprint-2-template-2.html
          • ...
          • blueprint-2-template-N.html
        • ...
        • blueprint N
          • blueprint-N-template-1.html
          • blueprint-N-template-2.html
          • ...
          • blueprint-N-template-N.html
        • base.html
      • wraps
        (conterá wraps que são funções/decorators personalizados que serão utilizados em qualquer route ou em funções)
        • wrap 1.py
        • wrap 2.py
        • ...
        • wrap 3.py
      • __init__.py (inicialização da web, onde irá criar um blueprint separado somente para a web, importar e adicionar as blueprints filhos a ela)
      • blueprint 1.py (blueprint 1 filho da web)
      • blueprint 2.py (blueprint 2 filho da web)
      • ...
      • blueprint N.py (blueprint N filho da web)
  • venv
    (Diretório do ambiente virtual)
  • .env (arquivo em que é interpretado/carregado pelo flask automaticamente, no qual é usado para definir variáveis de ambiente)
  • main.py (arquivo utilizado para rodar a aplicação)
  • requirements.txt (arquivo em que contem todas as bibliotecas necessárias para rodar a aplicação)
